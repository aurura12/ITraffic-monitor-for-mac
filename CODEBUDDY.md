# CODEBUDDY.md

This file provides guidance to CodeBuddy Code when working with code in this repository.

## Project overview

iTraffic for macOS is a lightweight, open-source, per-process network speed monitor. It is a native macOS 14+ menu-bar app (SwiftUI + AppKit + Charts, raw `sqlite3` C API). There are **no Swift Package Manager dependencies**; the Xcode project is generated from `project.yml` via [XcodeGen](https://github.com/yonaskolb/XcodeGen).

The app shows live upload/download per process/app and records per-minute history to a local SQLite database, visualized in a dashboard.

## Common commands

Prerequisites: Xcode (with command line tools), `brew install xcodegen`. macOS 14+ is required (the repo targets macOS 14.0).

Regenerate the Xcode project (required whenever `project.yml`, source files, or targets change):

```bash
xcodegen generate
```

The generated `ITrafficMonitorForMac.xcodeproj` is committed, so commit it together with the changes that required regeneration. `project.yml` is the source of truth.

Build and launch without opening Xcode (builds Release **unsigned**, installs the app to `/Applications/ITraffic.app`, and launches that copy so Finder's Applications folder shows the current build):

```bash
./scripts/update.sh
```

Useful modes (see the script header):

```bash
./scripts/update.sh --debug      # Debug build + LLDB attach
./scripts/update.sh --logs       # launch + stream app logs (`log stream`)
./scripts/update.sh --telemetry  # launch + stream iTraffic subsystem logs
./scripts/update.sh --verify     # build, launch, verify process is running
./scripts/update.sh --clean      # wipe build output (/Applications copy + dist), then build+launch
```

Sanity check for `update.sh` itself (static greps, no build):

```bash
./scripts/update_test.sh
```

Run the full test suite:

```bash
xcodebuild -project ITrafficMonitorForMac.xcodeproj -scheme ITrafficMonitorForMac \
  -configuration Debug -destination 'platform=macOS' -derivedDataPath dist/DerivedData \
  test CODE_SIGNING_ALLOWED=NO
```

Run a single test:

```bash
xcodebuild -project ITrafficMonitorForMac.xcodeproj -scheme ITrafficMonitorForMac \
  -configuration Debug -destination 'platform=macOS' -derivedDataPath dist/DerivedData \
  test CODE_SIGNING_ALLOWED=NO \
  -only-testing:ITrafficMonitorForMacTests/TrafficBarHoverTests/testNettopParserHandlesQuotedCommaInProcessName
```

Notes on signing: this repo has **no Apple Developer Team configured**. Builds are unsigned (`CODE_SIGNING_ALLOWED=NO`), and in Xcode you run with "Sign to Run Locally". Do not require real signing for normal build/test/dev work. Only the Network Extension targets (not in the default project) would need a team.

There is no linter or CI configuration in the repo.

## Code layout

- `ITrafficMonitorForMac/` — app target (module name `ITraffic`, bundle id `com.foamzou.ITrafficMonitorForMac`)
  - Root: `AppDelegate.swift` (entry point, wires everything), `Network.swift` (nettop frame → UI/DB pipeline), `Store.swift` (`SharedStore` singleton registry + SwiftUI environment objects), `ProcessEntity.swift`, `MenuBar.swift`, `Utils.swift` (process identity/icon helpers), `GeneratedBuildInfo.swift` (auto-generated by a build script phase; do not edit)
  - `Model/` — observable state: `ListViewModel`, `StatusDataModel`, `RealtimeRateStore` (2s ring buffer), `PerAppRateStore`, `LocalizationManager`
  - `Dashboard/` — SwiftUI dashboard/settings/export views, `DashboardViewModel`, `Theme`
  - `Service/` — the traffic engine: `NettopRunner`, `ProxyAttributor`, `TrafficRecorder`, `TrafficDatabase`, `UTunTrafficSampler`, `TrafficFilterManager`/`TrafficFilterStatsStore`/`TrafficFilterTotals`, `FreeAttributionCalibrator`
  - `NetworkFilter/` — Network Extension providers + shared code, **NOT compiled in the default project** (excluded in `project.yml`); requires a signed Apple Developer Team. Do not treat it as part of the free build.
- `ITrafficMonitorForMacTests/` — unit test target, hosted inside the app (`@testable import ITraffic`). Two classes: `TrafficBarHoverTests`, `TrafficFilterTests`.
- `scripts/update.sh` — build/run script described above.
- `docs/superpowers/{plans,specs}/` — dated design specs and implementation plans; the most recent ones cover traffic attribution/accounting. `CURRENT_PROGRESS.md` (in Chinese) tracks the current state of the VPN/attribution work.

## Runtime data flow

1. `AppDelegate.applicationDidFinishLaunching` sets an `.accessory` activation policy, creates `MenuBarController` + `Network()`, and starts `Network.startListenNetwork()`. It also starts `ProxyAttributor` and `UTunTrafficSampler` (diagnostic only).
2. `NettopRunner` (Service/NettopRunner.swift) spawns the system `nettop` wrapped in `/usr/bin/script -q /dev/null` for a pseudo-TTY (both the TTY wrapper and keeping stdin open are deliberate anti-CPU-spin mitigations — do not remove). Command: `/usr/bin/nettop -P -d -L 0 -J bytes_in,bytes_out -t external -s 2 -c`. It drops the first cumulative frame after each spawn (only delta frames are real) and detects frame boundaries with a 0.35 s read-idle debounce.
3. `Network.handleFrame` receives one frame of CSV lines, parses them into `ProcessEntity` values (quote-aware CSV parser in Network.swift), and sums the frame's raw totals.
4. The frame goes through `ProxyAttributor.attributedEntities(_:)` (bounded re-attribution, see below), then `HelperAttributionRegistry`, then `SharedStore.recorder.record(...)` persists it.
5. UI state is updated on the main thread: total rates → `StatusDataModel`, per-process rows → `ListViewModel`, rate history → `RealtimeRateStore`/`PerAppRateStore`.

## Data model / persistence

`TrafficRecorder` → `TrafficDatabase` (thin, serialized wrapper over the raw sqlite3 C API; all DB access happens on a dedicated queue). Key schema invariants:

- Per nettop frame, one `traffic_samples` row (`sample_id` is the **idempotency key**; replaying a frame is a no-op) plus `sample_allocations` rows (per-app bytes), committed in a single transaction.
- **Conservation rule**: summed allocations must equal the frame's raw in/out bytes, or the sample is rejected (non-conservative). `nettop` is the *only* historical byte source; the Network Extension and utun sampler never write history.
- `app_traffic` holds minute-bucket aggregates (the legacy path) and is UNIONed with finalized sample allocations via the `accounted_traffic` view, which dashboard queries read from.
- Legacy migrations merge older app keys (`verge-mihomo`, `mihomo`, `Unattributed VPN`, …) into the stable `Clash Verge` key.

Dates are stored as local-day indices (`day`, local days since 1970-01-01) computed in Utils.swift via Calendar — don't replace with naive `timeInterval / 86400` math (off-by-one in negative-offset timezones).

## Attribution & process identity (core domain — read this before touching it)

Why proxy piercing exists: with a local proxy/VPN active, `nettop -t external` credits every proxied byte to the proxy process (Clash Verge/Surge), while real apps show ~0 because their proxy-bound traffic is loopback. The fix is best-effort and deliberately conservative:

- `ProcessEntity.appKey`/`displayName` (ProcessEntity.swift) compute a stable per-app identity: bundle id when available, canonical `Clash Verge` naming, helper/daemon/WebKit processes attributed to their owning app (Utils.swift: `owningAppForProcess`, `outermostAppBundlePath`, WebKit "<HostApp> Networking" handling), and CLI tools shown as "<terminal> · <process>". Cache entries are validated against process launch dates so PID reuse cannot poison them.
- `Service/ProxyAttributor.swift` (~1500 lines, the trickiest file) polls Clash (HTTP `127.0.0.1:9090` or Clash Verge's Unix socket) and Surge connection tables plus `lsof` socket snapshots to map source port → owning pid, then computes per-app deltas between polls. **Hard constraints**: attribution is settled only within the same nettop frame, only against the proxy row's own byte budget; it never invents bytes, never carries unpaid "debt" into a later frame, never proportionally spreads residuals, and never falls back to the foreground app. Unknown/unattributable bytes stay on the proxy row (`Clash Verge`).
- The complex attribution logic is implemented as **pure top-level functions/types** (`settleProxyWindow`, `consumePendingProxyCredits`, `PendingProxyCredit`, …) so unit tests can exercise it without a live proxy or nettop. When adding logic, follow this pattern (no live-process dependencies in the pure core).
- `UTunTrafficSampler` is an optional diagnostic sampler only; it must not feed history totals.

## UI

- Menu-bar status item (`MenuBar.swift`) embeds live ↑/↓ rate text; the popover shows the process list and menu items (open dashboard/settings, quit). Small value types (`MenuBarSnapshot`, `MenuBarRateText`) are extracted and unit-tested.
- Dashboard (`Dashboard/`) is a single window with six tabs: Overview, Trends, Monthly Top, Realtime, Heatmap, Apps + per-app detail and CSV/JSON Export. Queries are async passthroughs on `TrafficRecorder`. `DashboardViewModel` uses a prioritized refresh plan + sequence tokens to discard stale async results.
- All user-facing strings go through `L()` / `LocalizationManager.text(_:)`, keyed by the English string with a zh-Hans dictionary in `LocalizationManager.swift`. Add new strings there (English key + Chinese value); missing keys fall back to English. App language and appearance persist in `UserDefaults`.

## Pitfalls & conventions

- `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` and bundle settings live in `project.yml`; bump there and regenerate.
- `GeneratedBuildInfo.swift` is overwritten by a pre-build script phase every build — never edit or commit manual changes to it (it is gitignored).
- After regenerating with `xcodegen`, verify the default project still excludes the two Network Extension targets and that the app target has no `CODE_SIGN_ENTITLEMENTS` (the free build runs under "Sign to Run Locally").
- Attribution claims: without a real signed Network Extension, only *total* byte conservation is guaranteed; per-app VPN/proxy bytes are best-effort. Never describe the unsigned Network Extension code as "working/installed/enabled" just because it compiles. Recent decisions and remaining work are tracked in `CURRENT_PROGRESS.md` (Chinese) and the dated specs under `docs/superpowers/specs/` — read those before modifying attribution/accounting behavior.
- Version history is in English-commit-message form on `main`; single-developer project, docs are a mix of English (code comments, README) and Chinese (CURRENT_PROGRESS, some plans).
